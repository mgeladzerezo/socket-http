Life of a request

  1. acceptOne acceptor thread takes the connection and checks the connection limit; over it, the client gets a 503 immediately.
  2. readBytes go into an incremental parser that is fed whatever arrived, however split. Header and body deadlines run from the first byte.
  3. routeThe router picks the most specific pattern and runs the middleware chain around the handler.
  4. writeThe head is built once, small bodies are copied into one buffer, files go straight from the page cache with transferTo.
  5. log and countA Common Log Format line is written and the latency histogram is updated, then the connection waits for the next request or closes.
